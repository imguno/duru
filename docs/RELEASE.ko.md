# 배포 절차

[English](RELEASE.md) · 한국어

## 배포 전

1. 패키지 버전을 갱신하고 GitHub Release의 배포 안내를 준비합니다.
2. 로컬 검사를 실행하고 스테이징·공개 파일에 비공개 자료가 없는지 확인합니다.
3. 깨끗한 소스 복사본으로 wheel·sdist의 소스 포함 여부와 독립 설치한 API를 검증합니다.
4. 해당 커밋의 CI·의존성 감사와 독립 리뷰를 확인합니다.
5. GitHub의 보호된 `pypi` 환경과 PyPI Trusted Publisher를 연결합니다.
   PyPI API 토큰을 저장소 시크릿에 넣지 않습니다.

메인 브랜치 푸시는 CI만 실행합니다. **GitHub Release를 발행하면** 배포가 시작됩니다.
패키지 버전이 `0.1.0`이면 태그는 `v0.1.0`처럼 정확히 일치해야 합니다.
릴리스 워크플로가 태그·버전과 CI를 검사하고 배포 파일을 다시 검증한 뒤,
분리된 `pypi` 환경 작업이 GitHub OIDC로 발행합니다. 기존 버전은 덮어쓰지 않습니다.

## 최초 레지스트리 설정

PyPI에서 실제 GitHub 소유자·저장소와 워크플로 `publish.yml`,
환경 `pypi`를 사용해 pending/trusted publisher를 등록합니다.
Duru의 소유자는 `imguno`, 저장소는 `duru`입니다.
PyPI 계정 확인과 필요한 2단계 인증은 PyPI에서 관리합니다.

**Duru를 먼저 배포**하고 깨끗한 환경에서 PyPI의 `duru==VERSION` 설치를
확인한 뒤, 그 의존성 버전을 사용하는 Galmuri를 배포합니다.
워크플로를 커밋하는 것만으로 PyPI에 발행되는 것은 아닙니다.

## 설치 검증과 되돌리기

새 가상 환경에서 발행한 정확한 버전을 설치하고 `python -m pip check`와
README의 읽기·조건부 쓰기 예제를 실행합니다.
이전 로컬 체크아웃이 아닌 의도한 패키지를 불러오는지 확인하세요.

문제가 있으면 추가 배포를 중단하고 원인을 확인합니다.
기존 파일을 덮어쓰는 대신 새 버전을 발행합니다. PyPI의 yank는 별도 관리 작업입니다.
앱을 업그레이드하기 전에는 저장소의 기능 지원과 리비전 동작을 확인하세요.
패키지를 이전 버전으로 돌려도 원격 저장소에 쓴 내용은 되돌려지지 않습니다.

이 체크아웃에서 `python tools/release.py --output .verification/release`를 실행하면
Duru의 소스·wheel 배포 파일과 의존성 없는 설치, 읽기·조건부 쓰기를 검증합니다.
Galmuri의 CLI와 사용 스킬은 Galmuri 배포에서 검증합니다.
